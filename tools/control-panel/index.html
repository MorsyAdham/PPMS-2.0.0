Users & access

Add people, reset passwords, and decide what each person can see and do. Changes reach a signed-in user straight away — disabling an account signs that person out.

What each role can do

ViewerReads plans, dashboards and reports. Cannot change anything.
OperatorRecords production: starts/completes steps, notes, issues, X-ray.
PlannerEverything an Operator can do, plus edits the plan and schedule.
Master AdminFull access, including users, audit log and all modules. There must always be at least one.

Modules = which plans the person can open (KD1, KD2, F100). Export = can download reports and Excel/PDF files.

Accounts

Click Edit to change a person's details, role, access or password. Every change is written to the audit log as control-panel@local.

Plan versions

Each module (KD1, KD2, F100) can hold several revisions of its production plan side by side. The Baseline is the original plan. Users pick a version inside the app. To keep users safe, this panel will not archive a baseline or the last available version of a module. Archive hides a version from that list (anyone viewing it is moved to another one); Restore brings it back. Nothing is deleted here, and new versions are created inside the app.

Announcements & maintenance mode

Show a message across the top of PPMS for every user — for example before an update. Maintenance mode makes the whole system read-only (for everyone except Master Admins) while you work on data or publish, so nobody's edits get lost.

Message banner

Preview — what users will see:

Good to know

  • Open sessions update within seconds; new sign-ins see it immediately.
  • In maintenance mode users see their role as “Viewer” and every edit button is hidden. Switching it off restores their real role.
  • Maintenance mode is enforced by the app. Until the security rebuild (SC-01) is live, the database itself would still accept writes made outside the app.
  • Typical update: turn on the banner and maintenance mode → publish on the Releases page → check the site → turn everything off.

Releases & app version

Control which version of the PPMS app users are running. Publish sends your latest code to the website as a new version. Restore puts an earlier version back if a release causes problems. Users get the update through the version chip in the app's top bar.

Help & glossary

What the terms in this panel mean, and how to do common jobs.

Terms

Live site
The PPMS website everyone uses (GitHub Pages). It contains exactly the app/ folder as of the last publish.
Test site / app-v2
The new secure version being built (Vercel). It becomes the live site at the security cut-over.
App version (v166…)
Goes up by one with every publish or restore. Users see it in the top bar and are prompted to load a newer one.
Commit / push
Commit = save a checkpoint of your code on this computer. Push = upload those checkpoints to GitHub. Publishing needs committed code.
Plan version
A revision of a module's production plan (e.g. Baseline Plan, Revision 2). Not the same as the app version.
Audit log
The permanent record of every sign-in and change in PPMS.
Maintenance mode
Temporarily makes PPMS read-only for everyone except Master Admins.
Public (anon) key
The database key inside the website code. Anyone can see it, so the database must not trust it — fixing that is the SC-01 work.
Service key
The all-powerful database key this panel uses. It lives only in tools/control-panel/.env on this computer and must never be shared or committed.

Common tasks

  1. Add a person — Users & access → + Add user → give them their email and password.
  2. Someone forgot their password — Users & access → Edit → type or generate a new password → Save.
  3. Someone left — Users & access → Edit → untick “Account active” (keeps their history). Delete only accounts made by mistake.
  4. Release an update — Announcements (warn users) → Releases → Publish to live site → check the site → turn the banner off.
  5. An update broke something — Releases → Version history → Restore the last good version.
  6. Before risky data work — Database & backups → Back up now.
